# 通用画布布局

用户已确认事件关联布局方式，并要求将实验收敛为通用 CLI 功能。

## 行为与验收

`md pull --bot <智能体>` 后运行 `md layout [--ws <工作副本>] [--out <新目录>]`。无需手写改动脚本，不依赖智能体名称、节点 ID、业务关键词或人工指定分区。只在本机计算，产出 `after.json`、SVG 图片、可缩放 HTML 预览和 JSON 检查报告。打印目标身份、坐标变化、事件距离、重叠、面积及仅布局推送命令。

`md push --layout-only` 默认预演，用户确认计划码后才保存草稿。复用 `canvas/save`、备份、账本、回读和 `restore --layout-only`。布局命令不新增任何远端写入口，不运行模型或插件。

## 布局规则

1. 按真实实线建立有向图。以连通链路为排版单元，节点真实尺寸、端口位置和分支顺序进入 Graphviz dot 分层布局。结构性分区从入口后的主要分支及其可达集合识别，共用后续只保留一份。
2. 事件动作与入口按事件 ID 匹配，禁止按名称猜测。多个调用方共用入口保留一份；一个事件有多个入口则保留全部关联。未找到入口的事件只报告，不补节点。
3. 对跨链路事件，以动作右侧到入口左侧的距离为目标移动整段链路。单一调用方优先靠近上游，共用入口综合多个调用方；反馈和自触发允许回跳。不得承诺所有事件都朝右或全部紧邻。
4. 节点不新增重叠。相邻链路移动时避免增加跨链路实线穿过节点或实线交叉；报告剩余实线几何问题。面积和事件距离是不同目标，报告面积变化，不承诺全部指标同时改善。
5. 容器和嵌套子节点作为整体移动，保留内部相对位置、尺寸和父子关系；父子关系不一致、悬空或成环则停止。便签作为视觉块保留。清除移动后失效的旧绝对拐点，端点、端口、connector 和 router 保留。

## 安全与兼容

- 只允许非连线 `position` 和连线 `vertices` 变化；数组顺序、ID、数据、样式、尺寸、端口、事件及会话定义均保持。
- 有内容修改的工作副本不能混入布局推送，需使用独立草稿副本。布局标记为不可自动 rebase 的本地变换，避免在新结构上重放旧坐标。
- 远端拓扑、几何、尺寸、端口、容器、类型或事件 ID 变化阻止旧布局推送；只改话术或非布局样式时保留最新内容。确认码绑定实际最新草稿和保存内容。
- 无效坐标、重复 ID、悬空连线、无效端口等输入失败时不改变工作副本，不写远端。预览只包含节点名称、类型、端口及几何，不导出 prompt、代码、身份或输入数据。
- 保持单文件 Node >=18 分发。内嵌 Graphviz WASM，不要求安装原生 dot、Python 或浏览器；新依赖固定版本并包含许可证。
- 使用现有隔离分支开发，版本升为 1.6.0；`npm run build` 仅写开发产物，发布产物仍只由 release 生成。

## 验证

用本地假服务验证布局预演、确认保存、只改坐标、并发保护、布局回读及撤回。图形用例覆盖不同尺寸、多端口分支、多个上游共享入口、同名不同 ID、多入口、未匹配事件、反馈、容器和便签、空图及非法图。打包测试在 Node 18 上从无依赖目录运行布局并检查 SVG/HTML。真实太极草稿仅用于离线验收，不写远端、不试跑。
