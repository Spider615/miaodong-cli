# 外部用例与批量改（md test import --from-file / md test edit）

## 什么时候用

- 把 Excel、飞书表格、聊天记录这类外部数据批量建成回归用例：先写一段脚本把源数据转成 JSONL（一行一条用例），再用 `md test import` 导进去。
- 已有的用例要成批改（换断言、补聊天历史、改名字）：写一个改动脚本，用 `md test edit` 先预演，用户同意后再确认。
- 用脚本生成，不要逐条手写：分类和字段映射是机械规则，脚本能保证一条不漏；AI 该做的是写规则，不是逐条执行规则。

## 导入

```
md test import <集> --bot <智能体> --from-file cases.jsonl          # 新建测试集
md test import <集> --bot <智能体> --from-file cases.jsonl --into   # 导进已有的集
```

### 一行一条用例

| 字段 | 含义 |
|---|---|
| `name` | 必填，前后空格会去掉；同一个测试集里不能重名。溯源信息（源文件第几行、分类）写在这里 |
| `trigger` | 触发类型（20 个之一）。不写时按简写推：`event` → 事件触发，`image` → 收到图片，`text` → 收到文本 |
| `text` | 文本消息的内容，只用于文本用例 |
| `image` | 最后一张图的 URL。图片用例不能再写 `text` |
| `event` + `data` | 事件名（md 按名字换成 id）；`data` 是事件变量，变量名要在这个事件里有 |
| `input` | 完整的触发输入，要和 `trigger` 一起写，不能和上面的简写混用。没有简写的触发类型只能用它 |
| `history` | 此前的上下文：字符串（记成用户说的；图片写裸 URL），或 `{"role": "user" 或 "assistant", "content": "…"}` |
| `vars` | `{"会话变量名": 值}`，md 按名字换成 id；字符串、数字、布尔、数组类型的变量会核对值的类型 |
| `expect` | 断言，写法见下一节；可以写一种，也可以写成数组 |
| `scenario` | 场景名或场景路径（`父/子`）；这个区有场景树时挂上去 |
| `dimension` | 分类。有的区不保存，别指望它，分类写进 name |
| `strict` | `true` 时严格校验 |
| `mocks` | `{"plugin": [...], "sql": [...]}`，原样写进插件、数据库的 mock |
| `_` 开头的字段 | 你自己的备注，md 不看 |

别的字段一律报错。比如把 `expect` 拼成 `expected`：不报错的话，就会建出一条没有断言的用例。

### expect 的写法

| 写法 | 意思 |
|---|---|
| `"应说明退款流程"` | 用大模型判断回复符不符合这句描述 |
| `{"reply": {"similar": "已为您登记", "threshold": 0.8}}` | 回复和这句话语义相似（阈值默认 0.75，和秒懂自动生成的一样） |
| `{"reply": {"equal": "好的"}}` | 回复和这句话一字不差 |
| `{"handover": true}` | 转人工 |
| `{"event": "发送"}` | 发出了这个事件 |
| `{"event": "发送", "params": {"text": "应说明退款流程"}}` | 发出了这个事件，而且事件变量 text 符合描述（每个变量的写法同 reply） |
| `{"raw": {...}}` | 原样写入的断言（一条或数组） |

- 回复要经过事件才发出去的智能体（消息 → 延时回复 → 发送），要核对回复内容，就用 `event` + `params` 去核对「发送」事件里的文本。只写字符串的话，md 会去找「发文本」动作，这类智能体永远不通过。
- 打标签、写字段这类断言 md 不生成：它们两份内容的字段名不一样，写错了秒懂不报错，断言就永远不生效。要用的话，先在秒懂页面上建一条，再 `md test cases <集> --bot <智能体> --out x.jsonl` 导出来，照抄那条断言写进 `raw`。

### 例子

```jsonl
{"name": "退款-第2行", "text": "我想退款", "history": ["之前问过课程价格"], "expect": "应说明退款流程并给出申请入口"}
{"name": "看图-第3行", "image": "https://example.com/b.jpg", "history": ["这张截图是什么意思", "https://example.com/a.jpg"], "expect": {"reply": {"similar": "这是订单详情页"}}}
{"name": "延时回复-第4行", "event": "延时回复", "data": {"text": "课程怎么退"}, "expect": {"event": "发送", "params": {"text": "应说明退课流程"}}}
{"name": "投诉-第5行", "text": "我要投诉你们", "expect": {"handover": true}, "scenario": "售后/投诉"}
{"name": "新好友-第6行", "trigger": "new-friend", "input": {"contactId": "c1"}, "expect": "应发送欢迎语"}
```

### 怎么建模

- 触发输入只放「触发这一轮」的那条消息；这之前的对话都进 `history`。
- 图片用例：最后一张图写 `image`；用户另外发的文字、前面几张图，按时间顺序写进 `history`（图片写裸 URL）。不要把用户的文字写进 `text`：在秒懂里那是图片自带的说明文字。
- 触发类型一共 20 个，只有文本、图片、事件三种有简写。别的写 `trigger` + `input`。字段拿不准，就先在秒懂页面上建一条同类用例，用 `md test cases --out` 导出来照抄它的触发输入，只换业务值。

### md 导入时做了什么

1. **本地先校验全部用例**：
   - 查什么：JSON 格式、name 重复（`--into` 时还和集里已有的比）、触发写法、事件 / 会话变量 / 事件变量 / 场景的名字。
   - 有任何错误就一条都不写，带行号列出全部错误（退出码 1）；改好文件再导。
2. **先写 1 条读回来**：
   - 关键字段（name、触发、会话数据、断言）被秒懂丢了：撤回这 1 条（新建的集也删掉），报出是哪些字段；
   - 非关键字段（比如 dimension）被丢了：只提醒。
3. **其余每批 50 条**，写完按 name 读回来拿 id。
4. **挂场景**：按 `scenario` 分组挂上去；没有场景树的区跳过，并说明。
5. **审计**：
   - 逐条逐字段比对；
   - 挂之前和之后各看一次场景树，计数的变化和挂的条数对不上就提醒（通常是旧批次重复挂着）。

输出的汇总行是「提交 N · 回读 N · 挂场景 N · 缺失 N」。有缺失或关键字段不一致时退出码是 1，并列出是哪几行。

写到一半出错（网络断了、秒懂 5xx）时：
- 报错会说测试集是新建的还是已有的，可能已经写进去一部分。
- 先 `md test cases` 看写进去了哪些。
- 再用 `--into` 重导同一个文件时，已经写进去的 name 会被第 1 步拦下：把那几行删掉，只导缺的。

## 批量改

```
md test edit <集> <脚本.mjs> --bot <智能体>                    # 预演：列出改哪几条、改了哪些字段，给计划码
md test edit <集> <脚本.mjs> --bot <智能体> --confirm <计划码>  # 用户明确同意后才执行
```

脚本写法和 `md apply` 一样：默认导出一个函数，直接改 `cases` 里的用例对象（改的是副本，改坏了不影响秒懂）。

```js
export default ({ cases, h }) => {
  // 退款类的用例：断言改成核对「发送」事件里的回复文本
  for (const c of h.pick(/^退款/)) {
    c.canvasActionOutputAssertions = h.expect({ event: '发送', params: { text: '应说明退款流程' } });
  }
  // 给某一条补聊天历史
  const [one] = h.pick('投诉-第5行');
  one.sessionMemoryCustomData[h.historyVarId()] = h.history(['上周已经投诉过一次']);
  h.log('退款类改成核对发送事件；投诉-第5行补了历史');
};
```

| h 里的函数 | 做什么 |
|---|---|
| `h.pick(条件)` | 挑用例：名字、名字数组、正则，或者函数；给的名字找不到就报错 |
| `h.eventId(名字)`、`h.varId(名字)`、`h.historyVarId()` | 按名字取事件 id、会话变量 id、「消息历史」的 id |
| `h.expect(写法)` | 按导入时 `expect` 的写法生成断言数组 |
| `h.history(条目)` | 按导入时 `history` 的写法生成「消息历史」的值 |
| `h.log(文字)` | 写进预演的输出 |

- **只能改这些字段**：name、dimension、触发类型、触发输入、会话数据、mocks、断言、严格校验。下面这些都会报错，什么都不改：
  - 改了别的字段（id、场景挂载、审核状态……）；
  - 增删用例；
  - 把 name 改成空的或重名的。
- **计划码绑定每条改前和改后的内容**：预演之后，集里的用例被人改了、或者脚本改了，确认时就对不上，要重新预演、重新给用户看。所以脚本里不要用随机数、当前时间。
- **确认后的顺序**：先把全部用例备份到本机（`~/.miaodong/md/tests/<区>/<智能体 id 前 8 位>/backups/`），再逐条全量更新，最后读回来核对。
- **要用户同意**：批量改会写秒懂，和删测试集一样，要用户明确同意这次的清单。

## 坑（都实测过）

- 建用例的接口不返回 id，md 按 name 读回来对，所以同一个集里 name 不能重名。
- 有的区不保存 dimension：写进去读回来是空的。分类、溯源信息写进 name。
- 用接口建的用例直接是「已审核」；从执行记录导入的是「未审核」，但未审核的也照样会跑。
- 场景树是整个智能体共用的：重复导同一批数据，场景计数会翻倍，回归会跑重复的用例。md 导完会对账提醒。
- 断言写错时秒懂不报错，这条断言永远不生效。所以 md 只生成实测过的写法，别的用 `raw` 照抄页面上建出来的。
- 事件触发的外部用例还没实测跑过：第一次用先跑 1 条，看结果对不对。
