# 导入客户资料到知识库（md kb import，写库）

## 什么时候用，什么时候绝不用

- **只在处理客户资料时用**：用户明确要把一份客户资料导进某个库，或者要删掉旧文档重建。
- **查 case 时绝不用**：查 case 时知识库只读（`md kb list / pull / find / why`）。查出库的问题（没审核、答案错、缺 FAQ、分数不够），只报告给用户，由用户决定；不要为了修 case 去生成导入包。
- 写进去**立刻生效**：知识库没有草稿和发布这一层，所有引用这个库的智能体马上就用上新内容。
- 花钱：写知识库扣不扣秒懂积分还没实测过。积分不足时 md 会停下，可以续跑。

## 导入包

一个目录，按客户资料生成：

```
客户A-售后资料-0925/
  manifest.json   目标库、来源资料
  faqs.jsonl      要新增的 FAQ，一行一条
  docs.jsonl      要新增的文件：文件名 + 切好的段落，一行一个文件
  deletes.jsonl   要删的旧 FAQ、旧文件：精确 id + 名字
```

```jsonc
// manifest.json
{ "schema": 1,
  "kb": { "id": "<完整 32 位 id>", "name": "售后 FAQ" },
  "source": { "note": "客户 9 月给的售后手册和价格表",
              "files": [{ "name": "售后手册.docx", "sha256": "<64 位>" }] } }
// faqs.jsonl
{ "key": "f001", "question": "课程怎么退款", "answer": "在订单详情页……" }
// docs.jsonl
{ "key": "d001", "name": "价格表-瑜伽系列", "paragraphs": ["……", "……"] }
// deletes.jsonl
{ "type": "doc", "id": 123, "name": "价格表（旧）" }
{ "type": "faq", "id": 7001, "question": "课程怎么退款" }
```

- 目标库的完整 id 和名字：`md kb list` 能看到名字和 id 前缀，完整 id 在 `md kb pull` 的本机副本 `meta.json` 里。
- 要删的 id：从 `md kb pull` 的本机副本里查（`faqs.jsonl`、`files.jsonl`），问题 / 文件名照库里的原样写。
- 来源资料的 sha256：`shasum -a 256 <文件>`。没有来源资料的包 md 不接。
- 只有「加」和「删」：改一条 FAQ 就是删旧的、加新的（新的 id 会变）。
- 校验从严：不认识的字段、包内重复的问题 / 文件名 / key、空内容，都会报错，一条都不写。文件名最多 30 字、每段最多 1000 字。

## 流程

1. `md kb import <包目录>`：预演，只读。会查这些：
   - 目标库：按 id 找，库名要和包里写的一样。
   - 要删的：id 还在、问题 / 文件名没变；带图片、素材或知识标签的 FAQ，认不出审核状态的 FAQ，带知识标签的文件，都不能删（撤回时恢复不了）。
   - 重复：新 FAQ 和库里原有、又不删的 FAQ 完全一样，拦下；很像的（≥ 0.9）只提醒。同一个导入包在这个库上已经导入过、还没撤回，拦下（要接着做就 `--resume`，要重来先撤回）。
   - 引用这个库的智能体：线上版和草稿里哪些节点在用。
   - 要删的文件里有超过 1000 字或空的段落：只提醒，撤回时可能写不回去。
2. 闸门全过才给计划码。把预演交给用户：目标库、增删条数、引用这个库的智能体、很像的 FAQ、各种提醒。
3. **用户明确同意后**，运行 `md kb import <包目录> --confirm <计划码>`。不能替用户确认；包或要删的内容在预演之后变了，计划码就作废，要重新预演。
4. 执行顺序（md 自己按这个做）：快照 → 备份要删的（含原文件，只存本机） → 试写一条读回核对 → 建 FAQ、建文件和段落 → 逐字核对 → 审核 FAQ（从这一步开始生效） → 等向量化 → 删旧的（先和备份比对、再查一遍能不能恢复）。
5. 怎么认「这次建的」（写进去的新 FAQ、文件，秒懂不返回 id）：每个写请求发之前，md 先记下要建什么、库里原来有哪些；发完再列（没认全会隔一会儿再列，最多约 8 秒）。**只自动认「请求刚发完那几次列表里、唯一一条内容一模一样的」**：FAQ 问题和答案都一样，文件同名、是手工文件、还是空的。别人建的（哪怕问题、文件名一样）一律不写、不删。请求写进去了、回复丢了，也认得回来。之后才出现的一模一样的：FAQ 要用户确认才认，文件永远不认（另建一个）；一模一样的不止一条：一条都不认。
6. 确认之后 md 会给这个库上锁：同一个库同一时间只有一个 md 在写。另一个 md 正在写时会停下（退出码 5），等它做完再来。

## 停下了怎么办

先把输出里「停在「…」」那一行原样告诉用户。

| 停下的原因 | 意思 | 下一步 |
|---|---|---|
| 备份不全 | 段落没拉全、原文件下载失败，或者要删的现在恢复不了；还一条都没写 | 查明原因后续跑，或者撤回（什么都没写，撤回很快） |
| 试写的读回来和包里的不一样（秒懂改了内容） | 试写的那条已经删了 | 内容会被秒懂改写，**别续跑**；先查清楚，要撤回就 `md kb revoke` |
| 发出去了、在库里找不到 | 网络、积分等原因断了，写的时候库里也没多出别的：就是没建成 | `md kb import --resume <导入id>`，用户同意后 `--confirm`；认得出的不会重复建，没建成的重发 |
| 发出去了、在库里对不上，写的时候库里多出来对不上的（列出了 #id） | 那几条可能是秒懂改写了内容的这次写的，也可能是同一时间别人加的；md 不动它们 | 把列出来的原样告诉用户，请用户在秒懂上看一眼：是这次写进去的，就撤回，再在秒懂上手动删掉；不是，续跑（预演会再列一遍，**确认就是认定它们不是这次建的**）。同一条可疑两次，md 不许再续跑，只能撤回 |
| 续跑预演：库里有和这条一模一样的 FAQ，是这次请求之后才出现的 | 可能是这次的请求晚落库了，也可能是别人按同样的内容建的 | 原样告诉用户：**确认续跑就是认定它是这次建的**（撤回时会删它）。用户不确定（比如同事可能导过同样的资料），就别续跑，先撤回 |
| 续跑预演：库里有同名的空文件，是这次请求之后才出现的 | md 不认它、不往里写，续跑会另建一个 | 续跑没问题；它要是这次晚落库的，请用户之后在秒懂上删掉这个空文件（撤回也会列出来） |
| 库里有不止一条和它一模一样的 | 分不清哪条是这次建的（请求落了两次，或者两个人同时导了同样的内容）；md 一条都不认、不删 | 不能续跑。撤回（不会动它们，会列出来），再请用户在秒懂上决定留哪条 |
| 等向量化 | 新内容还没全部就绪（默认最多等 8 分钟），旧的还没删 | 过一会儿再续跑 |
| 删旧的：要删的内容在备份之后被人改过 / 现在恢复不了 | 有人改了问题、答案、文件名、段落，或者配了图、打了标签；一条都没删 | 让用户决定：撤回这次导入，或者按现在的内容重新生成导入包 |
| 知识库列表翻页不稳 | 列表有重复、有漏的，md 不拿半截列表去认 id | 过一会儿再续跑 |
| 文件（#id）里的段落和要写的对不上 | 这次导入建的文件在停下期间被人改过，或者秒懂改写了内容；md 不删它、不再往里写 | 请用户在秒懂上看一眼；不要这次导入了就撤回（撤回会先把它当前的内容备份到本机再删） |
| 已经发了两次，两次都对不上，不能再续跑 | 多半是秒懂改写了这几条的内容；两次多出来的都列出来了 | 撤回，再请用户在秒懂上手动删掉列出来的；按秒懂改写后的样子改导入包，再重新导入 |
| 续跑闸门没过：新 FAQ 和库里 #id 问题一样（导入开始之后才出现的） | 导入开始之后有人加了同一个问题 | 请用户在秒懂上看一眼再决定：保留它就撤回这次导入；要换成这次的内容，由用户在秒懂上处理掉它，再续跑 |
| 另一个 md 进程正在写这个库 | 退出码 5，什么都没写 | 等它做完再来；确认那个进程已经不在了，才按提示删锁文件 |
| 续跑被拒：已经发了两次，之后才出现一模一样的（列表延迟） | 秒懂的列表或者落库延迟很长，md 不在事后认；多出来的空文件列出来了 | 撤回，再请用户在秒懂上删掉列出来的空文件；这种情况要反馈给维护 md 的人（要调大发完之后再列的次数） |
| 这个库的锁上次接管到一半、接管的进程没做完就退出了 | 退出码 5，什么都没写（极少见） | 请用户确认没有别的 md 在写这个库，再按提示把两个锁文件都删掉 |

`md kb imports` 能看到本机全部导入记录和各自的状态。

## 撤回

- `md kb revoke <导入id>` 预演，用户同意后 `--confirm <计划码>`。
- 导入做完时如果说「另外：库里有 N 条和要建的一模一样、但是请求之后才出现的，md 没认」，把它原样告诉用户：那几条可能是这次晚落库多出来的，请用户在秒懂上看一眼、删掉多余的。
- 先从备份重建这次删掉的，再删这次建的，最后读回逐条核对。导入做到一半的也能撤回：建了多少删多少。「这次建的」「这次删的」都以导入记录为准：别人建的不删，别人删的不复活。
- 重建出来的内容一样，但 id 会变。库里已经有同一个问题 / 同名文件（不是这次建的，可能有人手动恢复了）：照样重建，预演会提醒会重复。
- 被删的文件重建成**同名手工文件**：段落和摘要照原样写回，检索效果一样；原文件传不回秒懂，留在本机备份里（撤回预演会给出路径），需要时由用户在秒懂上重新上传。
- 导入后被人在控制台改过的条目，预演会列出来：撤回会连改动一起删掉。删之前 md 会把这次建的所有条目当时的内容存进本机（导入记录里的 `revoke-backup/`），改动也找得回来。
- 重建一直过不去（同一条重建失败两次，不管是什么错：认不上、核对不过、段落写不进去、一直向量化不好）：预演会写「重建连续失败两次的：……接着重试就确认下面的计划码；要跳过它们的重建、先把这次导入建的删掉，加 --skip-rebuild 再预演」。把两个选择原样告诉用户，由用户选：选跳过就 `md kb revoke <导入id> --skip-rebuild`，预演会写「重建不了……」、原样在备份的哪里、要删的每一个 id，用户同意了再 `--skip-rebuild --confirm <计划码>`；撤回做完退出码 1，提醒用户在秒懂上手工恢复跳过的那几条。
- 有的重建再发也没用（库里一模一样的不止一条，或者两次都对不上）：不加 `--skip-rebuild` 的预演会停下（退出码 5）说明，只能跳过。
- 撤回说「库里有和备份里的旧内容一模一样的：#…——它就是旧内容，留着就行」：可能是同事照原样手工恢复的，也可能是撤回重建晚落库的，**别让人删它**（删了就连唯一一份旧内容都没了）。跳过重建的那条要是已经有一模一样的旧内容，md 会说「不用再恢复」。
- 撤回停在「删掉这次建的」、秒懂一直删不掉：可以请用户在秒懂上手动删掉那几条，再运行一次撤回（md 只删还在的）。
- 要删的旧内容在 md 删之前就被别人删了：撤回不会复活它（不是这次删的），预演和结果里会写清楚「没有重建、备份在哪」。
- 撤回本身中断了，再运行一次 `md kb revoke <导入id>`，会从停下的那一步接着做。
- **分不清是不是这次建的**（导入停下时列出来的那几条）：撤回不删。撤回做完会说「撤回做完了，但还有 N 条分不清……没删」，退出码 1——这时**不要跟用户说撤回完成了**，把列出来的原样告诉用户，请用户在秒懂上看一眼：是这次导入写进去的，就手动删掉，再运行一次 `md kb revoke <导入id>` 复查（都不在了才算干净）；都不是（比如同事同一时间加的），复查的输出里有计划码，用户同意后 `--confirm`，md 不再追踪它们，秒懂上什么都不动。

## 回执

每次导入或撤回之后回执：

- `区 / 企业 / 知识库`，导入 id；
- 状态：已完成（已生效），或者停在哪一步；
- 加了什么、删了什么（条数），引用这个库的智能体；
- 撤回命令：`md kb revoke <导入id>`；
- 「仓库代码没有改动」（如果确实没改）。

## 现在做不到的

- FAQ 的图片 / 素材附件；知识标签；新建或删除知识库本身。
- 撤回时把原文件传回秒懂（接口没找到）。
- 还没在真实秒懂上实测过：新 FAQ 是否默认未审核、新建之后列表能不能马上读到、段落长度上限、向量化要多久、扣不扣积分、真实的字段名、FAQ 有没有列表里看不到的属性（比如相似问法，删了重建会丢），都要先在测试库上验证。
