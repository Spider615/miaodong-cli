# 测试中心（md test）

## 命令一览

| 命令 | 做什么 |
|---|---|
| `md test sets --bot <智能体>` | 测试集列表；这个区有没有场景树 |
| `md test cases <集> --bot <智能体> [--out <文件.jsonl>]` | 用例汇总（触发类型、未审核、挂场景）；完整用例存本机 |
| `md test tree --bot <智能体>` | 场景树和各节点的用例数 |
| `md test import <集> --bot <目标> --from-execs <文件或 id> [--from-bot <源>] [--into]` | 从执行记录导入 |
| `md test import <集> --bot <目标> --from-file <cases.jsonl> [--into]` | 导入外部用例（格式见 `test-cases.md`） |
| `md test edit <集> <脚本.mjs> --bot <智能体> [--confirm <计划码>]` | 按脚本批量改用例（见 `test-cases.md`） |
| `md test run <集> --bot <智能体> [--version vX] [--rounds 1] [--concurrency 5] [--name <任务名>]` | 跑回归 |
| `md test status [<任务>] --bot <智能体> [--wait] [--timeout 540]` | 进度；不给任务时列最近的任务 |
| `md test results <任务> [<任务2> …] --bot <智能体> [--out <文件>] [--deep]` | 报告 |
| `md test stop <任务> --bot <智能体>` | 暂停（秒懂没有取消） |
| `md test drop <集> --bot <智能体> [--confirm <计划码>]` | 删测试集 |

测试集可以写名字、完整 id 或 id 前缀；任务可以写任务名、完整 id 或 id 前缀（至少 4 位）。

## 导入

- `--from-execs` 给 `md exec` 保存的搜索结果文件（文件里记着源智能体），或者逗号隔开的执行 id。
- 写秒懂之前，先取目标智能体（跨智能体时还有源智能体）的事件、会话变量列表。取不到就什么都不写，停下（退出码 5）。
  - 多半是这个区的版本不支持这两个接口。
  - 加 `--allow-preflight-errors` 能照导，但不核对、也不换 id，跨智能体的用例跑起来会空跑：先问用户。
- 跨智能体（源和目标不同）时，按名字把事件 id、会话变量 id 换成目标智能体的，全量回写后再回读核对。
  - 名字在目标里没有、或者有重名的，会列出来；这些用例跑前检查会拦下。
- 只给了 id、没给 `--from-bot`，md 先当作目标智能体自己的执行。导完发现事件或会话变量对不上，就把这次导进来的撤回；集里原来的用例不动。
  - 撤回后回读：没删干净就不删新建的集，并报还剩几条，用 `md test drop` 清理。
- 导到一半出错时，报错会说测试集是新建的还是已有的、可能已经导进去一部分。先 `md test cases` 看，不要直接重导：同一条执行再导一次，会再建一条用例。
- md 按用例 id 记下每条用例来自哪条执行；从文件导入时，还记下执行的时间、用户消息、线上回复。
  - 报告里的「调优中心执行 ID」「线上回复」两列就是它；用例在页面上改了名也对得上。

## 跑

- 跑前检查（都针对要跑的那张画布）：
  - 事件在这个智能体里存在，而且画布上有它的入口；
  - 会话变量存在；
  - 文本等其他触发器在画布上存在。
  - 取不到事件或会话变量列表，也算没通过。
  - 对不上的用例秒懂会「成功」但空跑，所以默认拦下；确认要照跑才加 `--allow-preflight-errors`，加之前告诉用户哪些用例会空跑。
- 预估 = 单价 × 条数 × 轮数。单价这样取：
  - 取两项里大的：md 上次看进度时记下的这个集的单价（包括被止损暂停的任务）；这个集上次跑完的任务的总花费 ÷ 真正执行了的条数（空跑不算）。
  - 两项都没有，用导入来源里源执行的平均花费；再没有就估不出。
  - 单价是 0 也当估不出：多半是那次全空跑。
  - 输出里「预计」后面的括号写着这次用的是哪一项。
- 确认：
  - 估不出一律要确认；
  - 超单次门槛（默认 ¥2）、当天累计超上限（默认 ¥10）、画布上有会真调外部系统的插件，都要确认；
  - 做法同 `md trial`：单独问用户，同意后加 `--confirm <码>`。
- 建任务前，先按预估在账本里记一笔（估不出的按每条 ¥0.3）。
  - 建任务时报「任务可能已经建了」：先 `md test status --bot <智能体>` 看最近的任务，不要重跑。

## 看进度、止损、账本

- `md test status <任务> --wait`：
  - 每 15 秒看一次，默认最多等 9 分钟；没跑完就再跑一次同一条命令接着等。
  - 查进度遇到网络错误或秒懂 5xx，连续 3 次才放弃。放弃时任务还在秒懂那边跑。
- 止损（只管 md 建的任务）：每次看进度都判断，不带 `--wait` 也判断。
  - 按已跑完条目的平均花费推算整个任务，超过额度就暂停任务。
  - 自动放行的任务：额度是单次门槛；另外，今天别的花费加上推算，也不能超过每日上限。
  - 用户确认过的任务：额度是「确认的金额 + 一个单次门槛」。确认时估不出的，确认的金额按每条 ¥0.3 算。
  - 没人看进度时，任务会在秒懂那边一直跑完，所以建完任务就接着 `--wait` 盯着。
- 账本跟着实际走（md 建的任务）：
  - 跑的过程中，这一笔的预留跟着推算往上调，并记下观察到的单价，下次估价用；
  - 停下来就记实际：跑完的用秒懂给的总花费；暂停、失败的按已跑完条目的花费，加上正在跑的条目按单价估。`md test stop` 暂停后也一样。
- 被暂停的任务，md 不能接着跑：重新 `md test run` 是整集再跑一遍，已经跑过的条目会再花一次钱。

## 报告

- stdout：每个任务的汇总（版本、次数、通过率、空跑、花费、耗时），外加前几条没通过的。还有没跑的条目时，汇总后面写「还有 N 条没跑」。
- 逐条明细总是存一份 JSONL：`~/.miaodong/md/tests/<区>/<智能体 id 前 8 位>/results/`。
- `--out` 按扩展名导出：
  - `.xlsx`：「汇总」「逐条」两张表，通过和不通过用不同底色；
  - `.csv`：带 BOM，Excel 直接打开不乱码。以 `=`、`+`、`-`、`@` 等开头的格子前面加了一个 `'`，防止 Excel 当公式执行；
  - `.jsonl`。
- 逐条的列：用例名、调优中心执行 ID、场景、用户消息、期望、是否通过、断言结论、实际回复、实际动作、花费、耗时、测试执行 ID、线上回复。
- 「是否通过」有四种：
  - 通过、不通过；
  - 空跑：跑了但什么都没执行（比如事件对不上），花费为空；
  - 未跑：任务被暂停或还在跑，这一条还没轮到。不算进次数和通过率。
- 实际回复的取法：
  - 优先取同一条链里的发送动作；
  - 没有的话，看断言里带出来的发出事件参数；
  - 还没有就加 `--deep`：按测试执行 id 去详情里取，每条约 2 秒。某一条取失败只在那一条上标出来，别的照取。
- 给两个任务时，按用例对齐：每个任务一组「通过 k/n」「回复」。

## 删测试集

- `md test drop <集>` 不带 `--confirm` 是预演：列出集名、用例数、挂了场景的条数、跑过的任务（还在跑或排队的单独说），给计划码。
- 用户明确同意后带 `--confirm <计划码>`：
  - 先把全部用例备份到本机 `backups/`，再删用例；
  - 回读确认用例删干净了才删测试集；没删干净就不删集，报还剩几条，再运行一次会重新预演；
  - 任务记录秒懂不删，会留着。

## 本机文件

`~/.miaodong/md/tests/<区>/<智能体 id 前 8 位>/` 下：

| 目录 | 放什么 |
|---|---|
| `sources/` | 导入来源：用例 id → 执行 id，以及执行的时间、用户消息、线上回复 |
| `tasks/` | md 建的任务：预估、单价、止损额度、对应的账本记录 |
| `exports/` | 导出的用例 |
| `results/` | 结果明细 |
| `backups/` | 删测试集前的备份 |

## 坑（都实测过）

- 空跑没有任何专门标记：`triggerExists` 仍是 true，只能靠「没有执行、花费为空」认出来。还没轮到的条目也是这样，只能靠状态（排队、在跑）和空跑分开。
- 逐条花费跑完那一条才有；任务总花费跑完才有，暂停后不给。
- 任务的 `averageCostInCny` 把空跑也算进分母，空跑多时会被拉低；md 估价用「总花费 ÷ 真正执行的条数」。
- 同一个智能体上的任务排队跑；只有暂停，没有取消。
- 测试中心会真的调插件和 HTTP；「发送」用户经验是不会真发到客户手里。
- 跨智能体导入的用例，断言来自源智能体，通过率没有意义，要看实际回复。
- `regression-test` 接口不用：它要求回归集至少 50 条，而且会忽略指定的测试集。
