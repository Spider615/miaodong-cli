# 通用画布布局

## 命令与产物

先拉取当前草稿，按 [改画布前先确认方案](../SKILL.md#改画布前先确认方案) 列出布局改法和预计涉及的节点，取得用户明确确认后再运行 `md layout`。它会暂存本地 `after.json`，生成预览也属于实际调整。

```bash
md pull --bot <智能体>
# 列出布局方案和预计节点清单，等待用户确认后继续
md layout --ws <工作副本> [--out <新目录>]
md check --ws <工作副本>
md push --layout-only --ws <工作副本>
```

`layout` 使用本地已拉取草稿，不接受 `--bot`，不隐式换目标。默认在工作副本创建新的 `layout-*` 目录，指定 `--out` 也必须是尚不存在的新目录。

- `preview.html`：离线可用，整理前/后切换、拖动缩放、按名称或 ID 搜索、选择事件接续。
- `optimized.svg`、`before.svg`：矢量图片，可放大检查；卡片为示意样式。
- `report.json`：节点数、连线数、重叠、曲线穿过节点/相交近似、事件距离、面积、完整移动 ID、输入输出指纹。
- `candidate.json`：包含当前业务配置和新坐标的本地候选快照，与暂存的 `after.json` 对应。

HTML/SVG 只包含名称、类型和几何；候选 JSON 含完整业务配置，只留在本机，不能公开上传。容器/子节点整体移动，保留内部相对位置，不自动改容器尺寸。

输入坐标的绝对值上限为 10,000,000，节点宽高上限为 100,000；异常大值会在计算前被拦下，避免布局或几何检查卡死。

## 布局语义

按实线连通关系排布链路，分支顺序以实际端口位置为准。较大的链路按主要分支及可达集合做结构分区，合流后的共用部分保留一份。

事件动作的 `nodePayload.eventId` 对应触发器的同 ID（入口兼容 `eventItem.eventId`）。不用名称猜关系。多个上游共同影响共享入口位置；一个事件有多个入口时全部纳入关联。未找到入口只在报告中提示，不增删节点或事件定义。

跨链路事件优先缩短动作右侧到入口左侧的距离。整段移动时避免新增节点重叠和跨链路实线交叉/穿过节点。实线或事件存在环时允许回跳，不宣称所有连接朝右。节点尺寸、共享入口位置和反馈可能使部分跳转仍较远，画布面积也可能增加。

连线使用 custom-curve 的已知曲线规则做采样近似；其他 connector/router 的精确绘制依赖编辑器，报告不等于浏览器加载验收。原有容器内重叠保留，不静默重排其业务节点。

## 保存与并发

`push --layout-only` 只允许非连线的 `position`、连线的 `vertices` 变化；节点数据、尺寸、ID、端口、父子结构、实际连线及事件/会话定义保持。旧绝对拐点会清理，让编辑器重画。普通 `push` 会保留远端布局，不能拿普通内容推送替代布局推送。

预演保留远端最新话术和非布局配置。远端节点/连线、尺寸、端口、容器、类型、事件 ID 或位置变化使旧布局失效；重新拉取后，核对方案和节点清单，超出已确认范围时先重新确认，再 `layout → check → push --layout-only`。计划码绑定实际保存内容，预演后草稿再变化，旧码不能用。

布局坐标不可在新图上自动 rebase。已有内容修改的工作副本会被拦，另拉草稿做布局；不可用整份替换或忽略检查开关绕过。

用户明确同意具体预览后才保存。回读会逐项检查移动坐标和拐点，失败不能宣称已核对通过。`status --remote` 可查覆盖；`restore --layout-only` 仅恢复布局并保留后来的业务内容，仍需预演和确认。
